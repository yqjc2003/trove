# Cachet（拾藏）市场定位与功能地图

更新时间：2026-11-13。本文只比较公开产品能力；“借鉴”指复刻用户问题与交互价值，绝不复制竞品代码、视觉资产或文案。

## 一句话定位

**Cachet 是面向多源收藏者的 Agent-native 回看库：把浏览器收藏、技术链接和视频收进一个可解释、可回看的个人空间。**

中文名“拾藏”表达“拾起值得的东西，妥善收藏”；英文 `Cachet` 同时让人联想到 `cache`（可找回的存储）与“品质印记”。上线前仍须完成目标市场的商标与域名检索。

## 核心优势

1. **多源，但不是大杂烩。** 浏览器书签、GitHub Star、视频 URL 与任何 HTTP(S) 链接在同一条管道里收录；技术收藏与兴趣内容无需切换工具。
2. **Agent-native，而不是绑定一套黑箱 AI。** Skill、MCP 与 REST 把收集放进 Codex/Agent 工作流；解读在 Agent 侧完成，服务端不保存 LLM 密钥、不主动抓取网页。
3. **个人语言由本人掌控。** 标签是唯一语义结构：Agent 先检查并复用已有词汇，用户可随时编辑，不强塞平台分类树。
4. **回看优先。** 收藏日期、未读状态、超期提醒、受控打开与笔记形成“收集 → 回看 → 理解”的闭环，避免单纯堆积。
5. **可迁移、可验证。** URL 幂等、JSON 导出、用户级数据隔离和 API Key 让用户不被锁进某个客户端。

## 推荐实施顺序

**P0（种子客户可感知）**：公开落地页和首轮 onboarding、浏览器一键保存、CSV/HTML/Raindrop 导入向导、可控稍后（1 天 / 1 周 / 自定义）与每日回看。

**P1（留存与迁移）**：全文索引、高亮、RSS/邮件入口、坏链检查、导入报告。

**P2（知识库扩展）**：带出处的问答、视频/播客转录、图片/PDF OCR、公开分享与协作、移动端 Share Sheet。

## 不应直接复制的做法

- 不把服务端改成替用户抓网页正文或持有模型密钥：这会破坏现有的 Agent 侧解读边界和 SSRF 防护。
- 不新增“分类”树：标签已是唯一的语义入口，新增分类会制造双重组织成本。
- 不在没有权限、成本和版权方案前保存整页副本、视频转录或邮件正文。

# Webhook

在「设置 → Webhook」填写自己的 HTTPS 接收地址，勾选需要的事件并保存。清空地址并保存即可关闭。每个账户独立配置；地址及其查询参数保存在用户资料中。保存后可点击「测试连接」，向已保存的地址发送不含收藏数据的 `webhook.test` 事件；收到 2xx 即显示成功。

| 事件 | 触发时机 |
| --- | --- |
| `item.created` | 首次保存链接 |
| `item.updated` | 修改或重复保存已有收藏，包括取消归档 |
| `item.archived` | 收藏进入归档状态 |
| `note.changed` | 笔记新增、修改或删除 |
| `item.sync` | 手动全量同步 |

手动点击「全量同步」逐条推送当前账户的全部收藏（含归档），与事件订阅选项无关。同步期间请保持页面打开，界面显示成功和失败数。

请求使用 HTTP POST，`Content-Type: application/json`，`X-CatchLinger-Event` 为事件名。主体示例（收藏包含其余状态、来源和时间字段）：

```json
{
  "event": "item.created",
  "sent_at": "2026-11-20T00:00:00.000Z",
  "item": {
    "id": "收藏 ID",
    "url": "https://example.com/article",
    "normalized_url": "https://example.com/article",
    "title": "标题",
    "tags": ["示例"],
    "notes": [{ "id": "笔记 ID", "body_md": "笔记", "created_at": "2026-11-20T00:00:00.000Z", "updated_at": "2026-11-20T00:00:00.000Z" }]
  }
}
```

每次推送包含操作后的收藏、标签及完整笔记快照；删除笔记后该笔记不再出现。接收方可按 `item.id` 做幂等更新。仅 2xx 视为成功；不跟随重定向。投递为尽力而为，失败或超时不会回滚收藏，也不会自动重试；可重新执行全量同步补发。自动推送会等待投递完成，全量同步分批并行发送，顺序不保证。全量同步期间修改或删除收藏可能影响分页结果，建议数据稳定后重新同步。

为避免访问服务器内部网络，只允许 HTTPS 和解析到公网 IPv4 的目标，不支持内网、localhost、纯 IPv6 或重定向。每次投递重新解析并固定连接地址。当前不提供签名；请使用接收端提供的随机、保密的 URL，并通过 HTTPS 保护传输。

部署者需先执行 `pnpm db:push` 应用数据库迁移。
